# 架构演进 · 素材视图层与多方法论（草案 v0.1，2026-07-09）

> 目标:把"素材 → 方法论 → 排期 → 发布 → 回溯 → 效果"这条链迭代到最优。
> 本文先讲清**当前架构在哪儿别扭**(客观),再给**目标模型**(提案 + 一个待定的关键岔路)。
> 权威方法论见 `架构与方法论.md`;本文是它在"素材/方法论"维度的深化。

## 一、当前架构的别扭点(基于 schema 实测,非猜测)

现状三层分离(能力/数据/引擎)是对的,骨架不动。别扭都出在**素材与账号的关系模型太扁**:

| # | 别扭点 | 现状(实测) | 为什么别扭 |
|---|---|---|---|
| G1 | 账号↔素材是**扁平多对多** | `素材表.适用账号` = link 到账号表(一个字段) | 无法表达"每个账号对素材维护自己的一套精选";同一素材对不同账号只是"适用/不适用"的 0/1,没有"用于哪个方法论、取哪个切面、选了多少" |
| G2 | 素材是**整文件粒度** | `素材表` 一行 = 一个整文件 | 同一段视频不能被不同账号以不同颗粒度复用;剪辑软件式"选中第几秒到第几秒/哪个区域/哪个语义切面"无处落 |
| G3 | 无**使用率账本** | 只有 `被引用次数`(整文件 formula 计数) | 说不出"软链了多少(linked%) vs 实际发出去用了多少(used%)";素材见底判断只能靠"有没有该类型",不够细 |
| G4 | 账号是**单模式** | `strategy.mode` 单字符串 + 单 `content_mix` + 单 `material_needs` | 无法"一个账号几种发布方法论";content_mix 只是内容类型配比,不是完整配方(切面+标题公式+正文公式+素材需求+节奏槽) |
| G5 | 回溯链**断在整文件** | `笔记表.关联素材` = link 整素材 | 回溯只能到"用了哪个文件",到不了"用了这个文件的哪一段/哪个切面、由哪套方法论产出";正向也没连到效果 |
| G6 | 排产**SKU-中心**,与"SKU 可选"矛盾 | `planner` 遍历衣服总表,只看挂了 SKU 的已拍素材 | 用户明确:很多账号发的东西**不挂 SKU**。非 SKU 素材对排产完全不可见,planner 会以为"没素材" |
| G7 | 效果闭环**未接线** | `COLLECT_METRICS` 只记 todo,没调采集;效果不回流影响排产/方法论 | "闭环转起来"缺最后一环:发了→采集→反馈→哪套方法论/切面有效→多排。学习环是断的 |

一句话:**当前把"素材"当账本行管,但用户要的是"素材是可被多账号、多方法论、以子片段粒度复用的资产,且用量可计"**——这是关系模型的升维,不是加几个字段。

## 二、目标模型(提案)

```
原始素材池(乱拍,引用不搬)
      │  ingest scan(agent 多模态看懂)
      ▼
方法论视图(每账号的每套 playbook 一套软链,AI 维护的精选)  ← G1/G2/G4 的答案
  每条 = 子素材选择:指向原始文件的一个切片(时间段/区域/语义切面)+ 语义维度标注 + linked 范围
      │  planner 按该号的【方法论 playbook】挑可发单元(SKU 可选)  ← G4/G6
      ▼
加工(skill:剪辑/文案/配图,按 playbook 选公式)
      ▼
排期(笔记表一行,状态机脊柱不变)
      │  人发布 → 回填链接 + 回填"用了哪些子素材/各用了多少"  ← G3/G5
      ▼
使用账本(used% 累加;笔记↔子素材↔原始文件 可回溯)
      │  采集 skill 取效果 → 回流笔记(热度分等)
      ▼
学习:哪套 playbook / 哪个切面表现好 → 调方法论权重(下一轮多排)  ← G7
```

### 关键决策(已定:2026-07-09,用户授权"按最佳实践判断,loop 中迭代")★

**决策 1 — 视图落盘(方案 A)**:账号素材视图 / 子素材 / 使用账本 = **盘上机器维护的软链索引**,非 Bitable 表。
承接"每(账号的每套方法论)维护一段软链接""AI 维护一套我们看不懂的链接""剪辑软件工程文件"的心智。
Bitable 仍是**生命周期账本**(笔记/状态/审批 = 唯一真值),`笔记表.关联素材` 存子素材 ID 引用作回溯锚点。
理由:视图/切片/语义维度是细粒度、机器拥有、会很多很碎——正是"表不当媒体库"要挡在 Bitable 外的东西;放盘可无限细化不污染账本。
(方案 B「落 Bitable 新表」已否:Base 大改 + 碎行爆炸 + 违"表不当媒体库"。)

**决策 2 — 视图挂在 playbook 上,不是账号上**:用户澄清"每种发布方法论对应一套软链接"。
故 **playbook = 一套配方(切面/公式/节奏权重)+ 一套素材视图(软链选择集)**。同一账号的不同方法论各有各的视图;
同一原始素材可被多个 playbook(跨账号、或同账号不同方法论)以不同颗粒度/切面复用。
视图落盘:`素材库/_views/{账号}/{playbook}/` 软链树 + `views/{账号}/{playbook}.jsonl`(子素材选择 + 语义维度)。

### 三层职责重划(方案 A 下)

| 概念 | 落在哪 | 说明 |
|---|---|---|
| 原始素材 | 盘(原位/素材库)+ `素材表`(整文件账本:路径/来源/SKU 可选) | 不变 |
| 方法论 playbook | `strategy.playbooks[]`(data)= 配方 + `view` 键 | **新**。每套 = 切面+公式+素材需求+节奏权重 + 指向自己的视图 |
| 方法论视图 | 盘:`views/{账号}/{playbook}.jsonl` + 软链树 | **新**。每 playbook 一套子素材选择,AI 维护 |
| 子素材 | 视图条目(clip_id + src + span + dims) | **新**。文件的一个切片/切面 |
| 使用账本 | 盘:`usage.jsonl`;锚点存 `笔记表.关联素材`(子素材 ID) | **新**。linked% / used% 可算,支撑回溯 |
| 排产/生成/回流 | `planner` + `orchestrator`(引擎,泛化) | 改解释逻辑,仍零账号特定代码 |

## 三、分期落地(哪些纯代码先行,哪些要 Base 迁移人工确认)

- **纯代码/纯 data,可自主推进(不碰 Base schema)**:多方法论 playbooks(G4,strategy 数据模型+planner+GEN)、SKU-可选排产(G6,planner)、账号视图/子素材/使用账本的**盘侧**数据结构与工具(G1/G2/G3,方案 A)、效果采集接线(G7,调已有 xhs_fetch seam)。
- **需 Base schema 迁移(人工确认,走 #8 迁移清单)**:`笔记表.关联素材` 若要存子素材引用(可先用现有 text 兼容,避免改 schema);任何新增 Bitable 字段。

每步硬门不变:6 个 `check_p*.sh` 全绿 + `ar_check`=100 + 每加能力带测试(见 memory `guanyun-dev-loop-gates`)。

## 四、里程碑评审加固(2026-07-09 · architect 用最佳实践评审后)

方向判定 **sound、可推进**。以下按业界成熟系统(NLE 子剪辑/bin、MAM per-project selects、DAM、
内容日历模板)加固,是评审找出的"开发中才知道"的潜在问题:

1. **单一真相源**(最大风险):使用账本 `usage.jsonl` = usage **唯一真值**;`笔记表.关联素材` = agent
   **只写一次的投影**(人不编),且改用 **text 字段存 clip_id**——不用 link,避免 Bitable link 强制整行引用。
   加一致性校验(盘 ledger 与表引用对齐,漂了报红)。杜绝两套真相源打架。
2. **clip_id 稳定性**(写盘前必须定死,前置 issue):`clip_id = 确定性哈希(原始文件稳定ID, span/切面描述)`;
   原始文件稳定ID 在 **ingest 时分配并存素材表**——不从路径/内容哈希派生(改路径/重编码不该断链)。
   提供 `relink` 操作(文件搬家重指向,类比 Premiere "Locate Media")。
3. **bin vs sequence 分清**:playbook 的 view = **bin**(稳定精选池),不是 sequence(每条笔记的拼装);
   "某条笔记实际用了哪些 clip" = 使用账本那层。两者别混。
4. **权重与争用策略**:显式 playbooks 的 weight 须归一(∑≈1,加校验);多 playbook 争同一稀缺素材 →
   **高权重优先**(或日内轮转);分配时给 usage 打 playbook_id 标签(知道被哪套方法论消耗)。
5. **可读逃生口**:机器 `views/{账号}/{playbook}.jsonl` 旁生成人可读 `.summary.md`(每子素材一句"为什么选它"),
   仅调试用、非真相源——发错料时人能回溯。
