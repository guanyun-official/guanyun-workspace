# 架构

## 一、模型 + Harness

> **Agency 来自模型。Agent 产品 = 模型 + Harness。**
> **Harness = Tools + Knowledge + Observation + Action Interfaces + Permissions**
> 模型做决策,Harness 执行;模型做推理,Harness 提供上下文。**模型是驾驶者,Harness 是载具。**
>
> —— 出处:`learn-claude-code`(Agent Harness 工程)

**Agent 永远是模型。** 我们不"开发 agent",我们**造 harness**。造好 harness,模型会完成剩下的。

**三句话记住它:**

1. **Base 不是 harness,是世界。** 它是唯一真源,**同时是人的驾驶舱** —— 人和 agent 看同一张表,不搞两套。
2. **workspace 是 harness 的领域那一半**(手/眼/法律 + 常驻知识);**运行时是通用那一半**(loop / 工具调度 / 技能加载)。
3. **技能是 harness 的 Knowledge 层,按需加载。** 它不是被调用的函数,是**读进模型脑子里的知识**。

## 二、技能是 Knowledge,不是函数

**技能 = harness 的 Knowledge 层**,机制是**渐进披露**:

| 层 | 在哪 | 什么时候 | 代价 |
|---|---|---|---|
| 目录(name + description) | system prompt | 启动时 harness 扫 `skills/` 注入 | ~100 tokens/技能,每轮都带 |
| 内容(SKILL.md 全文) | **tool_result** | agent 判断需要,才加载 | ~2000 tokens,用到才花 |

所以:

- **技能不是 `result = skill.f(x)`。** agent 把 SKILL.md **读进上下文**,它就变成了模型此时的知识,然后**模型自己动手**(用 Tools)。
- 把技能写成"被调用的函数",一复杂必然一堆 bug —— 那等于又把决策从模型手里拿走了。
- 技能可组合、可复用、**可以被别的品牌整包拿走**。唯一真源 = `qiaohe-skill` 仓;`skills/` 是 `install_skills.sh` 按 `skills.lock.json` 装出来的符号链接。

**技能 vs 权限(Permissions)的分界:**

> 能被违背而不出事的 → **技能**(知识,模型可以不听)
> **一旦被违背就是事故的 → Permissions**(代码焊死,模型没得选)

真事:技能 `writing-ootd-caption` 白纸黑字写着「只学结构、绝不抄原句」,模型**照样把爆款标题原封搬走**;拦住它的是 `guard.assert_no_source_leak`。技能写砸了最坏是稿子难看;红线破了是**抄袭发出去、AI 内容漏标、生产库被写** —— 那是事故。

## 三、唯一判据

> **这段代码是在替模型做决策,还是在给模型提供 Tools / Knowledge / Observation / Permissions?**
>
> - **替模型决策 → 错。删掉,把决策交回去。**
> - **提供工具/知识/眼睛/法律 → 对。那是 harness 的本分。**

推论:

- 「每天定时看网盘有没有新素材,有就打标」——**这是 agent 的操作**,哪怕天天发生。
  harness 只提供:`netpan.list_dir()`(手)、`tagging-material` 技能(知识)、`ingest.register()`(手)、`guard`(法)。
  **"这张图是什么类型" 是判断,归模型。**
- 「AI 生成的像素必须标 AI生成」——不是判断,是法规 → **Permissions**。
- 「状态 已批准 → 待发布」——确定性推进 + 过门 → **Action Interface**,由 agent 触发。

### 4.1b 世界的形状 —— **补了一个位置**(2026-07-14 用户点破)

素材表『类型』的 12 个值**把内容和形态焊在一个字段里**(「上身图」/「上身视频」是同一内容
两种形态;「面料·纹理特写」**只有图这一档**)。于是一条 **1.5 秒的面料特写视频没地方放** ——
代码必须给它个值,就长出了那条钳制:

```python
if kind == "video":
    return raw if raw in _VIDEO_TYPES else "上身视频"   # 视频文件强制落视频类
```

**看图模型多半判对了,harness 把它的正确答案覆盖掉了。** 后果一路滚:
库里唯一那条「上身视频」真身是 1.5 秒糊布料特写 → board 报「可用 1 条」(**真实 0 条**)
→ 补拍单少催一条 → 还有一条待审稿就是配着它出的。

**这不是代码 bug,是世界缺了个位置。** 已补:base 加『形态』(图/视频),『类型』回归纯内容
(上身/商品/形象/搭配/细节/面料·纹理/工艺/制作过程/空镜·场景/文物原件/文物对照)。
**钳制再也长不回来 —— 因为不需要了。**

> **它卡住时,先问"世界里有没有它要的那个位置",再问"代码要不要加个规则"。**
> 加规则是最容易想到的,也几乎总是错的。

### 4.2 测试 —— **已瘦成只剩红线**(2026-07-14 完成)

## 六、审查机制 —— **审查员必须是 agent,不能是脚本**

**问题**:整个 2026-07-14 的模式是 **用户发现 → 我修**。我自己一个都找不出来。

**根因**:我写的检查器(`alignment_audit`)只会**机械匹配**(regex / AST / 字符串)。
它能查"这个函数有没有人调用",但**永远查不出**:

> 「这段 `if` 是不是在替模型做决策?」

**这个问题只有模型能回答。** 所以审查员必须是 **agent**,不是脚本。

```
旧机制(已证明失效):
  我写 checker → checker 自己有 bug → 我修 checker → 它还是只会匹配字符串
       ↑ 2026-07-14 一天栽了四次:regex 把注释当调用点 / helper 没插进文件 /
         死码检查还用旧 regex / 钩子被当值引用却判死码

新机制:
  派子 agent 审(每个只问那一个判据)→ 它读代码、按判据判 → 报告 → 修 → 再派一轮
       ↑ 直到一整轮下来什么都找不出
```

### 审查员的唯一判据

> **这段代码是在【替模型做决策】,还是在【给模型提供 手 / 知识 / 眼睛 / 法律】?**

### 分片(每轮都派,不能等人发现)

| 子 agent | 审什么 | 找什么 |
|---|---|---|
| ① `orchestrator/` | 它本该**只有** Tools / Observation / Permissions / Knowledge | **判断被写死** · mock/stub · 人面骗人 · 死码 · 注释骗人 |
| ② `scripts/` | 只该有薄 CLI 入口 + 开发期的门 | **导轨** · mock · **测措辞的假检查** · 死码 · 悬空引用 |
| ③ 所有 md + 技能仓 | 文档不许携带旧模型 | **旧模型措辞** · 悬空引用 · 已下线的东西 · **互相矛盾** · 技能 frontmatter 坏了 |
