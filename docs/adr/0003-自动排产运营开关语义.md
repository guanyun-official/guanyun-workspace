# ADR-0003 · base「自动排产」运营开关的语义与唯一源

- 状态:已接受(2026-07-12,autoresearch 压测发现并落地)
- 相关:[[SOURCE_OWNERSHIP]]、`orchestrator/dispatch.py`、`docs/loop-每模式对齐.md`

## 背景
用户在飞书 base 账号表「自动排产」select(选项:**开启 / 暂停 / 跟随workspace**)想控制"某号发不发"。压测发现两个 gap:
1. 代码(dispatch 派活)**根本没读这个列**,只看账号 md 的 `cadence.posts_per_day`——team 在 base 点暂停无效(哑控制)。
2. 3 个选项里「开启」和「跟随workspace」行为**完全一样**,语义未定义。

## 决策
「自动排产」是 **base 侧运营开关**,是"该号今天发不发"的**唯一真相源**(team 在 base 点、dedicated agent 接手都读得到);账号 md 的 cadence 只定**默认节奏**。三态各有明确、不重叠语义:

| 值 | 含义 | dispatch 行为 |
|---|---|---|
| **暂停** | base 强制关(覆盖 md) | 不派 |
| **开启** | base 强制开(覆盖 md,即使 md `posts_per_day<1` 也派) | 派 |
| **跟随workspace**(默认) | 尊重 workspace md 的 cadence | md `posts_per_day≥1` 才派 |

唯一源边界:**base=开关(开/关/跟随),workspace md=节奏**。base 不重复定义节奏(不双写漂移);md 不管开关(那是运营态,归 base)。

## 实现
`orchestrator/dispatch.py`:`daily_assignments` 读账号表「自动排产」→ 纯函数 `_should_dispatch(sched, posts_per_day)` 决策。回归锁:`test_paused_account_skipped` + `test_sched_decision_three_states`。

## 后果
- team 在 base 点「暂停/开启」立即生效,谁接手都一致。
- 这类"base 声明了但代码没消费"的哑控制是一整类 bug(单测照不到)——见 `docs/autoresearch-压测体系.md` 持续审计。
