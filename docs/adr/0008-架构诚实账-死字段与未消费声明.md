# ADR-0008 · 架构诚实账:声明了但代码没消费的字段,逐一定性

- 状态:已接受(2026-07-13,场景压测双角度 agent 挖出后定性)
- 相关:`orchestrator/dispatch.py`、`orchestrator/guard.py`、`docs/架构与方法论.md §八`、ADR-0003(自动排产)

## 背景
场景压测(运营日常 + 内容形态两个 agent 逐行追代码)挖出若干"**文档/声明吹了、代码零消费**"的字段——正是"别信叙述里的成功"要防的。逐一定性,要么接上、要么文档说清,**不留误导性死码**。

## 逐字段决策

| 字段/声明 | 现状 | 决策 |
|---|---|---|
| `guard.assert_publish_quota`(单号日发上限) | 零调用者 | **保留,守未来路径**。它守的是"自动发布超限",而红线=**人发布、系统绝不自动发**→自动发路径根本不存在,故无消费点。当前发布上限由"人手发"这道门天然限。**非误留死码,是给将来若开自动发留的护栏**。 |
| `autonomy:full`(声明"连审批都免") | 零消费 | **有意不实现**。自动跳过人审 = 代发/代勾 AI 声明 = **违反红线**。故 autonomy 永不被消费是对的。§八 已改不再吹。 |
| `cadence.posts_per_day` / `cadence.pattern:burst`(节日一天多发) | `_should_dispatch` 只当布尔(≥1派)、`daily_assignments` 恒产 1 条/playbook | **语义待定再实现**。posts_per_day 是"账号日总量"还是"每 playbook 量"未定(账号多 playbook 时冲突);多发/爆发是**真 feature 非 bug**,需先定语义再动 `daily_assignments`(会波及 `_open_slots`/`_find_inflight_note` 的去重键)。当前=每 playbook/天 1 条(安全默认)。§八 不再吹"零代码即爆发"。 |
| `sourcing:trend_insert` | 曾不在 `SOURCING_HINT`(死声明) | **已补进 `SOURCING_HINT`**(不再死);但"插队优先级排序"未实现,急稿当前与常规稿同池——hint 已注明。真要插队优先级=改 workflow 代码。 |
| `笔记表.投手`(schema 有、`NoteFields` 无常量) | 未消费的 schema 字段 | **保留备用**(非死码)。按投手分派/统计未实现;要用先加 `NoteFields` 常量 + 消费逻辑。 |
| `config.BUDGET_MONTHLY_CNY=300`(月度成本告警阈值) | 全仓零消费(只是个标注释的 float);唯一真帽是单次 `PER_RUN_BUDGET_USD=1.2` | **纸面数字,需接硬闸**。成本已结构化落库(运行日志表`成本_元`),但没人 sum 它来 gate;Doubao 打标按图计费**在 LLM 帽外**。放量即失控(40号×3/天≈¥7200/月,300 拦不住)。→ ADR-0009 列为上量前必做:读`成本_元`月度聚合→超阈告警/停派活。(场景压测新挖,ADR-0008 补录) |

## 后果
- 死字段不再误导:要么被消费、要么在此如实定性。这些**都不是"改声明零代码"能变活的**(§八 曾如此暗示,已校正)。
- 真要做的两件(节日多发的语义 + 决定、蹭热点插队优先级)是 **workflow 代码级**,需要时按此 ADR 的语义前提再开工,不是配置。
- 反"叙述里的成功":架构文档吹的能力,以本账为准对齐代码现实。
