# 运行模式：开发 loop 与 运营 loop（两种循环，别混）

> 任何 session 进 workspace 先分清：你是在**做这个系统**（开发），还是在**跑内容工厂**（运营）。两者设的 /loop、monitor、目标完全不同。

## 关键澄清：运营环境 = 测试库，不是生产库

- **运营库（真跑内容用这个）**：`ZhzJbfkOsafwevsWkW8cfoILnfb`（历史叫"测试库"，但它就是运营环境）。`.env` 现在正指它 + `TEST_MODE=1` —— **当前配置本身就是可上线态**。
- **生产库 `N9IVbi6pTatJG5sqyTTcc0vSn4g`：焊死不碰**（用户 2026-07-08 拍板）。引擎守卫在 `TEST_MODE=1` 下物理上够不着它。
- **所以"上线" ≠ 切 `N9IVbi`、≠ 改 `TEST_MODE=0`。上线 = 在运营库 `ZhzJbf` 上挂 cron**（下方运营 loop）。旧的"P7 切生产 + 两把钥匙迁移"是基于误解，不执行。

## 一、开发 loop（把系统做得更成熟）

**何时**：改进 workspace 本身——补能力、修摩擦、清 issue。

**/loop（自定节奏，在 workspace 目录里贴）**：
```
/loop 继续完善 guanyun-workspace（开发 loop）：每轮从「开放 issue + ar_check 缺口 + 新构思的运营场景」挑一项最高价值的,实现→测试（单测 + 相关 check_p*.sh 必须绿,ar_check 保持 100）→keep/discard→提交；发现新摩擦即 to-issue；里程碑触发轻量 /verify；直到开发类 issue 清零且验收全绿想不出新缺口
```

**目标（可判定 Verify，keep 的门槛）**：
```bash
bash scripts/check_p4.sh && bash scripts/check_p6.sh && python3 scripts/ar_check.py | grep -q 'SCORE=100'
```

**Monitor（开发时盯三种坏事）**：
1. **测试转红（事件驱动,主信号）**：`orchestrator/`或`scripts/`变动→跑单测,红了报警。（无 fswatch 就每 60s 查 `git status --porcelain` 有变化则跑测试。）
2. **schema 漂移（事件驱动）**：定期 `dump_schema.py --base test` + `schema_diff.py 基线 schema/test`,字段被 UI 改名/删列即红灯（否则半夜引擎静默崩）。
3. **成熟度回归（时间驱动,每 30 分钟）**：全量 `check_p*.sh` + `ar_check`,任一不绿或 SCORE<100 报警（防加新功能弄坏旧的）。

**开发前沿（当前真实缺口）**：Planner→Note→状态推进已接通；下一主线是把「AI剪」从排产候选接到真实媒体加工动作（当前安全跳过，不把原料伪装成成片）、用真实素材填充各 Playbook View、以及真 API 验证（ARK 视频生成等，待 key）。

## 二、运营 loop（跑内容工厂，即"上线"）

**何时**：系统够成熟了,让它每天真的自己转。

**上线三步**（在运营库 `ZhzJbf` 上,当前 .env 即对）：
1. **人的一次性 UI 操作**（约 10 分钟,见 `docs/P2_手动配置清单.md`）：灵感表单已建；审批可选（推进器 hermes 卡片已通知,人在飞书翻状态列=审核）。
2. **挂时钟**：`bash scripts/install_cron.sh --install`（每日 09:00 的 daily 先把可执行「今日发」幂等建成 Note，再推进状态并发日报；工作时段每 30 分巡检 heartbeat；23:30 备份；周日复盘飞轮）。**注意 daily 即使 `--llm stub` 也会写运营库；`--llm real` 还会产生模型费用。**
3. **先 1 号试运行一周**：账号表只给一个账号排笔记；人每天只做 挂 SKU + 审卡片 + 手机发布勾 AI 声明 + 回填链接。达标（打回率<50%、成本可控、发布回执齐）再放量 4 号。

**运营 Monitor（上线后才需要）**：cron 失败即时告警、月成本超阈熔断、登录态过期催扫码——推进器 P4b 已内置（运维三件套 + heartbeat 巡检）。

**运营红线**：绝不自动发布（AI 只做到"待发布包",人手机发+勾 AI 声明）；单号≤3 篇/天、间隔≥2h；`N9IVbi` 生产库永不碰。

## 三、一句话决策

- 想**改系统** → 开发 loop（上面第一节的 /loop + 3 个 dev monitor + 验收全绿目标）。
- 想**跑内容** → 运营 loop（`install_cron.sh --install` 在 `ZhzJbf` 上,人只挂 SKU + 审批）。
- 两者可合流：开发 loop 每轮顺便构思一个新运营场景考验架构,扛不住就 to-issue 再修——让系统被真实场景推着长。
