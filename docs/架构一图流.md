# 巧荷架构一图流（给"不搞技术也能看懂"的一页）

> 一句话:**能力 = 可换的技能(skill),编排 = 薄执行器,真相 = 各有唯一的家。加需求 = 加技能,不改代码不改表。**
> 你的直觉对了:现状就是"一堆可替换的零件 + 技能很方便"。下面说清每个零件是谁、怎么拼。

## 五个"唯一源"（一个事实只有一个家,不双写）

```
        ┌──────────────── 人只碰这两处 ────────────────┐
        │  base(飞书多维表)              素材(云盘/素材库) │
        └───────────────────────────────────────────────┘
              │账本+脸                        │大媒体
   ┌──────────┴──────────┐            ┌───────┴────────┐
   │ Note状态机/账号注册表 │            │ 视频·图(整文件)  │
   │ 素材投影/效果数/需求lane│           │ 表只存相对路径   │
   └──────────┬──────────┘            └────────────────┘
              │读写
   ┌──────────┴───────────────────── workspace(本仓库 git)─────────┐
   │  账号声明·画像(发什么/怎么写)  +  薄执行器(编排)  +  schema契约   │
   │  local 特化技能(该号真实帖 few-shot)                          │
   └──────────┬───────────────────────────────────────────────────┘
              │调用(读owner→调skill→写owner)
   ┌──────────┴──── 技能仓库(独立 git,可复用"怎么做")─────┐
   │ 写作 writing-* / 采集 xhs-extract / 剪辑 video-editing │  ← 你说的"可替换的项目"
   │ 拆解 account-teardown … 换能力=换技能,薄执行器零改动    │
   └──────────────────────────────────────────────────────┘
        agent(Claude Code/Codex)=可换壳的手,无状态,换壳成本≈0
```

| 零件 | 是谁 | 装什么 | 换/加怎么弄 |
|---|---|---|---|
| **base(飞书)** | 账本 + 员工的脸 | Note 状态机、账号/内容tag 注册表、素材投影、效果数、需求lane | 人在飞书直接用 |
| **workspace(git)** | 声明 + 薄编排器 | 账号声明·画像、薄执行器、契约、local 特化技能 | 改声明=改行为,零代码 |
| **技能仓库(独立git)** | 可复用"怎么做" | 写作/采集/剪辑/拆解…每个一个目录 | **加能力=加技能,`skills.lock` 锁版** |
| **agent** | 可换壳的手 | 只负责执行,不存业务真相 | Claude Code / Codex 随便换 |
| **云盘/素材库** | 装大媒体 | 视频·图整文件 | 搬家只改根前缀 |

## 薄执行器怎么转（拿现在真跑的两个动作举例）

- **出稿**(`orchestrator/draft.py`):读账号声明 → 取该号方法论的 **生成技能** → 加载它的真实帖 few-shot → 组文案 + **选素材**(按类型/赛道从素材表挑) → 过红线闸 → 写飞书「草稿待发」。
- **回流**(`orchestrator/collect.py`,每周日):读「已发」note → 调 **采集技能(xhs-extract 非登录,不用我方账号)** → 写回点赞/收藏 → 按方法论复盘(哪套有效)。

两个动作都是**"读 owner → 调技能 → 写 owner"**;薄执行器自己**不含**"怎么写/怎么采/怎么剪"——那些全在技能里。所以:

- **换采集源 / 换剪辑工具 = 换个技能,薄执行器和飞书表都不动。**
- **加一种发法 = 写一条方法论声明 + 指一个生成技能,不改 schema。**

## 内容工厂全流程(每步 = 调一个技能,读写标了 owner)

```
拍素材(人) → 摄入素材(ingest,存按拍摄批次/挂赛道) 云盘+base素材投影
  → 薄执行器出【文案+选定素材】完整草稿   base「草稿待发」        ← 已跑通
  → 人审(改稿) → 人手机发布 + 必勾AI声明 + 回填链接   ← 两道人审=红线,不可自动
  → 周日回流采集(xhs-extract非登录)写回点赞/收藏  base效果数    ← 已接线
  → 按方法论复盘 → 调权重/提技能改进(人审PR)     workspace/skill
```

## 你确认的几点(都对)

- **剪辑用专门技能** ✓ `video-editing`(在 `skills.lock` 的 video-engine 源)。
- **效果回流每周一次** ✓ 周日 cron:采集 → 复盘(见 `scripts/install_cron.sh`)。
- **可替换、技能很方便** ✓ 正是设计初衷:技能独立版本化,想换/加改 `skills.lock` 装技能即可。
