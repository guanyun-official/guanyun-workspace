## 2. 架构定论(经多轮 + 2026 最佳实践研究)

**能力为中心,不是流水线为中心。** 系统 = 能力库(skills)+ 账本(owners)+ 执行器(agent)。做的每件事 = 调一个 skill 读写账本。

五个 owner,唯一源(细节见 SOURCE_OWNERSHIP.md):

| owner | 超能力 | 拥有 | 绝不拥有 |
|---|---|---|---|
| **base(飞书)** | 人能碰+永远在线+关系型 | 员工界面、Note 状态机、注册表(账号/内容 tag)、素材投影、效果数、**点对点需求 lane** | know-how、skill 版本、大媒体、开发 issue |
| **workspace(git,本仓库)** | 可版本可 diff | 账号声明+画像、**薄执行器**、schema 契约、local 特化 skill | 运行状态、大媒体、通用 skill 实现 |
| **skill 仓库(qiaohe-skill,独立)** | 可复用"怎么做" | 通用能力(写作/剪辑/拆解) | 某号怎么发、Base ID |
| **agent** | 可换壳的手,无状态 | 执行(定时/按需) | 业务真相(全在 owner 里) |
| **云盘** | 装得下大 | 大媒体 bytes | 生命周期状态、know-how |

**关键定论(回答历史纠结):**
- **workspace 要不要?要,但是"薄"**——它是**薄编排器**(声明 + 执行器 + 红线守卫),不是重引擎。2026 编排最佳实践:纯"一堆定时任务(choreography)"可扩展**但丢可追溯性**,不适合受监管流程;你们有红线(必勾 AI 声明、绝不自动发布)= 受监管 → **必须有薄编排层**。"编排即架构,但要薄。"
- **多 agent 还是装配 skill?**一个执行器 agent 加载不同 skill 就够;专职性在 skill,不在 agent。多 agent 只在需要并行/隔离时(agent 无状态,水平扩)。
- **触发**:定时 + 事件 + 自适应(agent 自算 next_run)。

## 3. skill 模型(两层,Anthropic 官方最佳实践)

- **每个 skill = 一个目录**(`SKILL.md`:frontmatter 只需 name+description,正文<500行 + `scripts/`/`references/`/`assets/`),用 **`create-skill` 建**,渐进披露、可组合。
- **两层**:
  - **通用能力**(remote 仓库 qiaohe-skill,保持独立干净可复用):`write-xiaohongshu`、`video-editing`、`account-teardown`、`explosive-teardown`(爆款模式用)…
  - **号/模式特化**(local skill,住 workspace,`compose` 通用能力):如已建的 `writing-amateur-ootd`。**杀手锏:特化 skill 里塞该号真实历史帖当 few-shot 例子**(已做)。
- `skills.lock.json` = 唯一清单,按 `source`(remote/local)管;"自带 vs 下载"无语义区别,全按 lock 装。
- **自由度**:写文案=高(创作+例子)、剪辑=中、红线动作(AI声明门)=低(精确)。

## 4. 账号/模式/素材模型(颗粒度对齐现实——纠正 TARGET_INVENTORY 的过度建模)

- **账号 = { 模式[] }**;**模式 = { gen_skill + 调性 + 素材来源 + 节奏 }**。现在一号一模式;加发法=加一个模式(多用一个 skill)。将来 AI 按爆款推荐新模式。
- **素材粗粒度**:就是图/视频。**不分衣服、不要 SKU、不要材质/颜色/工艺精细库**(你们"一顿拍、排列组合",不按衣服组织)。素材**按赛道(账号×模式)存**,不挂衣服。实抓已证:一批穿搭拍摄,图文号取图、视频号取视频。
- **"衣服/工艺/文物出处"** 这类不是每件商品一条 DB 字段,是**内容 know-how**(写考据用),归 workspace,不进 Base 商品目录。→ TARGET_INVENTORY 里"衣服总表保留一堆内容字段"要**大幅瘦身**。
- **两种内容来源**(衣服组合拍 / 爆款模仿拍·AI剪)= 素材上的一个`来源`标签,**不是两套结构**,下游都是"素材→笔记→发"。
- **点对点日常需求**(每天各种:分析号/找爆款/给拍摄建议/归类素材)= **调一个 skill(或 create-skill 新建)**,不预设表;base 留一条轻"需求 lane"接收、产物落回。**新需求 → 新 skill,不改 schema。**
- **子素材视图层**(现有 lib/material_view)颗粒度本来就对(material-centric、SKU 无关)——但**是过早的精致**,先不进骨架(见 §5)。
